# Loom 记忆与技能系统 PRD

> 状态：讨论稿<br>
> 关联：[核心 Agent PRD](v0.4-core-agent-prd.md)、[权限与数据生命周期 PRD](permissions-security-and-data-lifecycle-prd.md)

## 1. 产品目标

记忆保存“应当知道的事实与偏好”，技能保存“应当如何完成某类任务的可复用操作知识”。二者都能让 Loom 随使用变得更贴合用户和项目，但必须始终可见、可控、可撤销。

v0.4 的目标不是最大化自动记忆，而是建立一个可信闭环：**提出 → 审阅 → 应用 → 解释 → 更新/归档/删除**。

## 2. 用户问题

- 用户不想每次重复项目测试命令、架构约束和偏好。
- 用户担心错误、陈旧或敏感内容被自动注入未来任务。
- 用户需要知道某次结果是否受到某条记忆或技能影响。
- 维护者需要让高质量流程被复用，同时淘汰长期未使用或不再适用的规则。

## 3. 对象与作用域

| 对象 | 内容 | 默认作用域 | 例子 |
| --- | --- | --- | --- |
| Memory | 结构化事实、偏好、约束、关联来源 | user 或 project | “本项目使用 `cargo nextest`。” |
| Skill | 指令、参考文件、可选工具要求与生命周期元数据 | project 或 user | “按团队格式生成发布说明。” |
| Suggestion | 从会话复盘得到、尚未生效的候选项 | source session | “建议保存测试失败排查流程。” |
| Usage | 一次加载/调用/跳过/失败的记录 | session/run | “技能 X 因任务匹配被加载。” |

优先级建议为：会话显式指令 > 项目项 > 用户项 > 内建项。相同优先级冲突时必须显示冲突，而非不可见地随机覆盖。

## 4. 功能需求

### 4.1 创建与审阅

- M-01：用户可以显式创建、查看、编辑、复制和删除 memory/skill。
- M-02：会话复盘可产生建议，但默认不自动写入生效存储。建议包含来源会话、建议理由、内容、推荐作用域和敏感性标记。
- M-03：用户可接受、编辑后接受或拒绝建议；接受产生新版本，拒绝保留最小审计记录但不在未来加载。
- M-04：系统在保存前检测明显敏感值（密钥、令牌、Cookie 等）并阻止或要求用户改写；不得以“记忆”作为秘密存储。

### 4.2 发现、加载与解释

- M-05：每次运行产生上下文清单：候选项、被加载项、未加载理由（无匹配、被禁用、冲突、超预算）。普通输出显示摘要，verbose/JSON/ACP 提供细节。
- M-06：用户可按名称、作用域、标签、来源、更新时间和状态搜索 memory/skill。
- M-07：用户可以在单次会话或运行中禁用某项；禁用不得删除原项。
- M-08：上下文预算有限时，系统按明确规则裁剪，并向用户说明被省略的项和原因。

### 4.3 生命周期与质量

- M-09：每项维护版本、创建/更新时间、来源、作用域、状态（active、disabled、archived）和最后使用时间。
- M-10：usage 跟踪记录加载/调用/失败/跳过的最小信息；写入失败不阻断主 Agent 运行。
- M-11：curator 可标记长期未使用、引用失效或冲突的项为待审阅；归档须可恢复，不能直接静默删除。
- M-12：项目级项随项目保存/删除；用户级项不会因单个项目清理而删除。

## 5. 用户交互与命令契约

用户以“管理上下文”理解该功能，而非需要先理解内部存储。至少需要以下逻辑操作：

| 目标 | 逻辑操作 | 必要输出 |
| --- | --- | --- |
| 查看当前影响 | `context explain` | 加载项、来源、原因、冲突、预算裁剪。 |
| 管理记忆 | `memory list/show/create/edit/delete` | 作用域、来源、更新时间、状态。 |
| 管理技能 | `skills list/show/create/edit/delete` | 描述、工具要求、作用域、状态。 |
| 审阅建议 | `review pending/show/accept/reject` | 来源会话、建议差异、影响范围。 |
| 审查质量 | `curator` / `skill-usage` | 未使用、失败、待归档项及理由。 |

现有 CLI 的 memory、skills、skill-usage、review 和 curator 命令是实现基础；名称和帮助文案需对齐上述用户任务。

## 6. 验收标准

1. 创建项目级记忆后，相同项目的下一次运行在上下文解释中显示它；切换项目时不加载。
2. 一条被禁用或删除的项不再进入后续提示上下文，且用户能区分禁用与删除。
3. 自动复盘建议未被接受时不改变任何 active 项。
4. 冲突的项目/用户项被显式报告，最终应用规则稳定且可测试。
5. 一次 usage 或 curator 存储失败不会导致 Agent 任务失败。
6. 导出和删除遵守数据生命周期 PRD；敏感检测和拒绝保存路径有测试。

## 7. 非目标与开放决策

- v0.4 不让模型自行永久写入用户记忆。
- v0.4 不承诺跨设备同步或团队共享的冲突解决。
- 待决定：Memory 是否必须结构化 schema；技能是否允许执行任意安装脚本；项目与用户项的可见性如何跨 ACP/Bot 展示；过期阈值如何由用户配置。
