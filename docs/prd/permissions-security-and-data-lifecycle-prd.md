# Loom 权限、安全与数据生命周期 PRD

> 状态：讨论稿<br>
> 范围：CLI、ACP、MCP、工作流及 `.loom/` 用户数据；不替代操作系统、Git 或 MCP 服务自身的安全模型

## 1. 问题与目标

Loom 能读写文件、执行 Shell、使用浏览器和 MCP，并保存会话、记忆、技能与工作流产物。对开发者而言，这些能力有价值，也意味着权限、数据归属和删除后果必须比普通聊天工具更清楚。

目标是让用户在每次高影响操作前理解：**谁要做什么、影响什么范围、授权多久、留下什么数据、如何撤销或清理。**

## 2. 安全原则

1. **工作目录优先**：项目目录是默认上下文，不等于无边界系统权限。
2. **最小且分层授权**：读、写、执行、网络/MCP、浏览器、删除/发布分别评估。
3. **人可理解的确认**：提示展示工具、操作、目标范围和持久性，不能只显示内部工具名。
4. **拒绝安全失败**：无法确定路径、策略或权限时不执行高影响操作。
5. **本地数据由用户控制**：数据位置、保留期、导出和删除均可发现。
6. **密钥不出现在用户可见输出**：日志、错误、事件和诊断一律脱敏。

## 3. 权限模型

| 能力类别 | 默认策略 | 可选授权 | 必须记录的最小审计信息 |
| --- | --- | --- | --- |
| 读取工作目录内文件 | 允许并提示有效目录 | 无需逐次确认 | 工具、相对目标、会话/实例、结果。 |
| 写入/修改工作目录文件 | 请求确认或遵从明确用户任务策略 | 单次、会话、项目 | 变更目标、授权范围、结果。 |
| 工作目录外文件 | 默认请求确认 | 单次；项目范围需显式配置 | 规范化后目标、原因、决策。 |
| Shell/进程 | 请求确认，尤其是网络、安装、删除命令 | 单次、会话 | 命令摘要、cwd、退出状态。 |
| MCP/网络 | 首次连接和高影响工具请求确认 | 会话或已命名服务器 | 服务器、工具、目标域/资源、决策。 |
| 浏览器操作 | 导航/读页面按策略；提交表单、下载、上传、登录相关操作确认 | 单次 | 站点、动作、上传文件名、决策。 |
| 破坏性操作 | 永远需要明确确认 | 不允许“永久默认允许” | 目标、影响估计、确认者、结果。 |

ACP 已支持 `session/request_permission` 与 allow/deny 的会话交互；CLI 需要提供语义等价的确认/策略机制。没有交互能力的自动化必须使用明确配置的非交互策略，并在启动时显示其风险。

## 4. 功能需求

- S-01：每个工具调用按能力类别和目标路径/资源计算权限决策；不能因工具别名绕过策略。
- S-02：路径检查使用规范化路径并防止目录遍历；相对路径解析后才判断是否超出工作目录。
- S-03：用户可选择 Allow once、Allow for session、Deny once；项目级持续授权必须是显式、可查看的配置。
- S-04：确认被拒绝或取消时，Agent 得到明确、不可伪装为成功的工具结果。
- S-05：`--worktree` 在 Git 仓库的修改型任务中作为推荐隔离方式；创建、保留、清理或保留原因必须可见。
- S-06：工作流中的每一个 Agent 和子工具继承实例的权限上下文；不得因后台/并行执行跳过确认或审计。
- S-07：模型 API、MCP 配置、日志和错误输出不得打印 API key、Authorization header、Cookie 或完整环境变量。

## 5. 数据生命周期

| 数据 | 默认位置/归属 | 保留与清理要求 |
| --- | --- | --- |
| 项目配置、MCP、Agent/技能 | 项目 `.loom/` 或用户 Loom 配置目录 | 显示作用域；用户可导出、编辑、删除。 |
| 会话/checkpoint | 本地 Loom 数据库或项目关联存储 | 可列出、查看、删除；删除影响需说明。 |
| 记忆 | 用户或项目作用域存储 | 支持按项删除、来源追溯、导出。 |
| 工作流实例 | `.loom/instances/` | 提供实例清理策略；清理前显示磁盘影响。 |
| 日志 | 配置的本地日志路径 | 默认最小化；可设置轮转/关闭；脱敏。 |
| 临时 worktree | Git worktree 路径 | 无变更可清理；有变更必须保留或由用户明确处理。 |

- S-08：`loom data/status`（名称待定）应汇总本项目数据位置、大小、保留策略和可清理对象。
- S-09：删除会话、记忆、技能或实例时，命令必须显示确切目标与不可逆影响；批量删除需显式范围。
- S-10：导出只包含用户选择的对象；默认不打包密钥、日志中的敏感信息或工作目录外内容。
- S-11：遥测为 opt-in，默认不上传源代码、提示词、工具输出、文件路径或密钥。

## 6. 验收与发布门槛

1. CLI 与 ACP 对同类文件、Shell、MCP 操作产生等价的允许/拒绝结果。
2. 路径遍历、符号链接越界（平台支持时）、拒绝确认、取消确认和后台工作流均有测试。
3. 以模拟密钥运行时，日志、JSON、ACP 和错误输出均不含密钥文本。
4. 用户可从文档和命令中找到数据位置、删除方式及 worktree 清理结果。
5. 默认策略和例外策略均有可读的用户文档；禁止仅以源码注释作为安全说明。

## 7. 开放决策

1. CLI 默认采用每次写入确认，还是对明确的用户自然语言任务授予会话级写入？
2. 项目外读取是否默认禁止，还是允许但首次显著提示？
3. `.loom/` 是否应提供加密/凭据隔离，优先支持哪些平台？
4. 工作流非交互运行的批准策略如何携带、审计和过期？
