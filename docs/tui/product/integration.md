# 产品文档：集成架构

## 概述

Loom TUI 采用渐进式集成策略，与现有 Loom CLI 系统深度兼容。通过条件编译机制和事件适配层，TUI 功能作为可选特性集成到现有架构中，保持向后兼容性的同时提供交互式用户体验。

## 用户价值

- **无缝升级**：现有用户无需改变使用方式，传统功能完全保留
- **按需启用**：通过编译特性控制 TUI 功能，减少依赖和二进制体积
- **统一体验**：TUI 模式与传统模式共享底层逻辑，确保行为一致
- **灵活切换**：支持三种运行模式，适应不同使用场景

## 核心组件

### 条件编译层

通过 Rust 条件编译特性实现 TUI 功能的按需集成：

```toml
[features]
default = []
tui = ["ratatui", "crossterm"]
```

TUI 代码仅在 `tui` feature 启用时编译：

```rust
#[cfg(feature = "tui")]
mod tui;

fn main() {
  if args.interactive && cfg!(feature = "tui") {
    run_tui_mode().await;
  } else {
    run_traditional_mode().await;
  }
}
```

### 事件适配层

将现有系统的回调机制转换为 TUI 事件流：

```rust
// 现有回调接口
type StreamCallback = Arc<Mutex<dyn FnMut(Value) + Send>>;

// TUI 事件适配
let (tx, rx) = tokio::sync::mpsc::channel(256);
let callback = move |event: Value| { 
  tx.blocking_send(event).ok(); 
};

// 事件处理
tokio::select! {
  Some(event) = rx.recv() => { 
    self.handle_agent_event(event); 
  }
}
```

### 现有模块复用

- **display/ 模块**：复用 spinner 帧动画、终端检测、panel_format
- **run/agent.rs**：通过回调适配集成，无需修改核心逻辑
- **config/**：直接使用现有配置加载机制
- **agent-core**：直接使用 agent 运行引擎
- **stream-event**：直接使用现有事件类型定义

## 与其他层的关系

### 与应用层关系

- **配置共享**：TUI 模式与传统模式使用相同的配置系统
- **状态同步**：agent-core 的执行状态通过事件适配层同步到 TUI
- **命令统一**：CLI 参数解析统一，根据 flag 选择运行模式

### 与渲染层关系

- **终端复用**：继承 display/ 模块的终端管理能力
- **UI 增强**：在 ANSI 输出基础上增加内联视图和交互组件
- **降级兼容**：当 TUI 初始化失败时自动降级到传统模式

### 与交互层关系

- **输入扩展**：TUI 提供交互式输入框，补充传统 stdin
- **响应增强**：支持实时事件响应和用户中断
- **状态保持**：PaneStack 管理多面板交互状态

## 关键设计决策

### 1. 可选特性设计

**决策**：TUI 作为可选 feature 而非默认特性

**理由**：
- 减少依赖数量，保持轻量化
- 避免 TUI 依赖对传统模式的污染
- 支持在受限环境（如容器）中使用最小化构建

### 2. 回调适配而非重写

**决策**：通过事件适配层连接现有系统，而非重写 agent 运行逻辑

**理由**：
- 保持 agent-core 的稳定性
- 降低集成风险和测试成本
- 确保传统模式的行为不受影响

### 3. 三模式运行策略

**决策**：提供 TUI、传统、审批三种运行模式

**理由**：
- 满足不同用户场景（交互开发 vs 脚本执行）
- 支持 CI/CD 集成（传统模式）
- 提供渐进式升级路径（审批模式）

### 4. 内联视图优先

**决策**：TUI 采用内联视图而非全屏模式

**理由**：
- 保留终端工作流上下文
- 支持与其他 CLI 工具协作
- 降低用户认知成本

## 使用场景

### TUI 模式（--interactive / -i）

**适用场景**：
- 对话式编程，需要实时反馈
- 调试复杂 agent 行为
- 可视化工作流执行状态
- 多面板对比分析

**用户体验**：
- 内联视图，终端上下文可见
- 交互式输入框，支持历史和编辑
- 实时事件流，主动更新
- 面板管理，灵活切换视图

### 传统模式（默认，无 flag）

**适用场景**：
- 脚本集成，自动化工作流
- CI/CD 管道
- 管道连接其他工具
- 资源受限环境

**用户体验**：
- ANSI 文本输出到 stderr
- 无交互界面，参数驱动
- 执行完成后退出
- 最小依赖和资源占用

### 审批模式（--approve）

**适用场景**：
- 单次运行需要人工确认
- 安全敏感操作
- 半自动化流程

**用户体验**：
- ANSI 文本输出 + 关键点弹窗
- 混合式交互，平衡效率和安全性
- 支持批准/拒绝操作
- 保持传统模式的简洁性

## 集成兼容性

### 向后兼容

- 现有 CLI 参数和行为完全保留
- 无 TUI feature 时编译为传统 CLI
- 配置文件格式保持不变

### 向前兼容

- 新增事件类型自动适配到 TUI 事件流
- 显示组件复用现有逻辑，新功能自动可用
- 配置系统扩展不影响现有配置

### 降级处理

- TUI 初始化失败 → 自动降级到传统模式
- 终端不支持交互 → 回退到 ANSI 输出
- 事件流阻塞 → 超时保护，避免影响执行
