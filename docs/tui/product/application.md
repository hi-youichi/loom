# 产品文档：应用层

## 概述

应用层是 Loom TUI 系统的最顶层，负责协调所有子系统工作，为用户提供完整的多智能体协作体验。它是用户与系统交互的直接接口，管理整个会话的生命周期、用户配置和智能体集成。

## 用户价值

- **无缝多智能体协作**：统一的界面协调多个智能体工作，无需手动切换上下文
- **会话持久化管理**：支持会话恢复、归档和清理，保护用户的工作成果
- **灵活配置体系**：支持运行时动态调整模型、主题、通知策略等关键配置
- **实时响应体验**：通过事件驱动架构提供流畅的交互反馈

## 核心组件

### App 主循环
系统的核心调度引擎，使用异步事件循环协调用户界面事件和智能体事件：
- 接收和处理用户输入事件
- 接收和分发智能体消息事件
- 触发界面更新和重绘

### 会话管理器
- **SessionState**：会话状态机管理（空闲 → 提交 → 等待 → 流式输出 → 空闲）
- **SessionResume**：支持会话恢复和分支功能，实现工作连续性
- **SessionArchive**：自动归档完成会话，保持工作空间整洁
- **TranscriptReflow**：智能处理终端窗口大小变化时的对话历史重新布局

### 配置管理器
- **模型配置**：支持配置文件默认模型和运行时模型切换
- **Spinner 风格**：可自定义加载动画样式
- **通知策略**：智能检测焦点状态，仅在合适时机通知
- **审批策略**：灵活的敏感操作审批机制，支持会话级"始终允许"策略
- **主题系统**：提供多种视觉主题，支持实时切换

### 智能体集成层
- **传统回调模式**：与现有 Loom 系统兼容，支持标准 ANSI 输出
- **Channel 通信模式**：为 TUI 模式优化的异步通信，提供实时状态更新

## 与其他层的关系

- **依赖终端层**：应用层通过终端层组件显示用户界面，接收用户输入
- **控制渲染层**：协调渲染层进行界面元素的绘制和更新
- **管理交互层**：通过交互层处理复杂的用户交互逻辑
- **复用数据结构**：基于数据架构层的核心数据结构进行状态管理

应用层作为整个系统的协调中心，向上为用户提供统一的交互体验，向下调用各层的专业能力。

## 关键设计决策

### 双模式架构
同时支持传统回调模式和 Channel 通信模式，确保与现有系统的兼容性同时提供现代化的实时交互体验。

### 会话状态驱动
采用明确的状态机模型管理会话生命周期，确保系统行为可预测且易于调试。

### 运行时配置热更新
支持在会话过程中动态调整关键配置，无需重启即可获得个性化体验。

### 异步事件驱动
基于 Tokio 的异步架构，能够高效处理并发的用户交互和智能体消息。

## 使用场景

### 日常多智能体协作
用户启动 TUI 应用后，通过统一界面与多个智能体交互，系统自动协调智能体之间的通信和结果展示。

### 长时间会话管理
用户可以暂停长时间运行的智能体任务，关闭终端后再恢复会话，系统自动保存和恢复上下文。

### 个性化工作环境
用户根据自己的偏好选择模型、主题和交互策略，系统记住用户的配置选择。

### 批量任务监控
用户可以同时监控多个智能体任务的执行进度，通过实时通知了解重要事件而不打断其他工作。
