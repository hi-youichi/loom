# 产品文档：基础设施层

## 概述

基础设施层是 Loom TUI 系统的最底层，为整个系统提供基础技术支撑。该层负责处理与终端硬件的直接交互、异步运行时管理、以及底层的终端能力检测。基础设施层对用户不可见，但其稳定性、性能和兼容性直接影响整个 TUI 的用户体验。

## 用户价值

- **稳定运行**: 确保应用在不同终端环境下稳定运行，崩溃时能安全恢复
- **流畅交互**: 提供高性能的异步运行时，确保界面响应及时无卡顿
- **广泛兼容**: 支持各种终端环境，包括主流终端模拟器和非 TTY 环境
- **渐进体验**: 通过条件编译，让用户可以选择启用或禁用 TUI 功能

## 核心组件

### ratatui 终端 UI 框架
- **是什么**: 成熟的 Rust 终端 UI 框架
- **做什么**: 提供界面渲染、布局管理、文本处理等 UI 基础能力
- **为什么需要**: 避免重复造轮子，保证 UI 渲染质量和开发效率

### crossterm 终端控制库
- **是什么**: 跨平台的终端操作库
- **做什么**: 处理终端模式切换、键盘事件、终端尺寸检测等底层操作
- **为什么需要**: 提供统一的终端操作接口，屏蔽不同平台的差异

### tokio 异步运行时
- **是什么**: Rust 异步运行时框架
- **做什么**: 管理异步任务、事件循环、多线程调度
- **为什么需要**: 支持 AI 对话的流式输出和后台任务的并发处理

### 终端检测
- **是什么**: 终端环境能力探测
- **做什么**: 检测终端是否支持颜色、光标控制、历史行操作等特性
- **为什么需要**: 根据终端能力自动调整 UI 功能，确保兼容性

### ANSI 工具
- **是什么**: 标准 ANSI 转义序列工具
- **做什么**: 处理文本颜色、样式、光标控制等终端显示功能
- **为什么需要**: 为传统模式和 TUI 模式提供统一的文本格式化能力

## 与其他层的关系

- **支撑终端层**: 为终端层提供原始终端操作能力和事件流
- **支持应用层**: 为应用层提供异步运行时，支持多事件源并发处理
- **渲染基础**: 为渲染层的 ratatui 组件提供底层渲染支持
- **条件集成**: 通过条件编译，不影响传统模式的性能和依赖

## 关键设计决策

### 双模式架构
传统模式和 TUI 模式共享基础设施，但 TUI 组件可选编译，确保向后兼容性。

### 渐进增强
基础设施层先检测终端能力，然后逐步启用相应功能，而非全有全无。

### 安全恢复
确保应用异常退出时终端状态能正确恢复，避免终端处于损坏状态。

## 使用场景

用户在日常使用中不会直接接触基础设施层，但其影响体现在：
- 终端窗口大小调整时界面自动适配
- 粘贴大段文本时的性能表现
- 终端失焦时的桌面通知触发
- 异常情况下的终端状态恢复
- 非终端环境（如管道、脚本）中的自动降级
