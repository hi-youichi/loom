# Codex CLI TUI 交互设计文档

## 概述

本文档描述 Codex CLI TUI 的用户交互流程、界面布局、按键映射以及视觉反馈机制。帮助理解用户与 TUI 的完整交互链路。

**来源仓库**：`https://github.com/openai/codex`（`codex-rs/tui/` crate）

---

## 1. 界面布局

### 1.1 整体视图

Codex TUI 采用**内联视图（Inline Viewport）**，不占用全屏终端，而是在终端历史中嵌入一个聊天区域：

```
┌─────────────────────────────────────────────────────┐
│ 终端历史（正常滚动区域）                                │
│ 用户之前的 shell 输出                                  │
│ $ cd ~/dev/myproject                                   │
│ $ ls -la                                              │
│ $ git status                                          │
│                                                        │
├─────────────────────────────────────────────────────┤  ← viewport 顶部
│ ┌─ User ──────────────────────────────────────────┐ │
│ │ 帮我优化这个 Rust 函数                            │ │
│ └──────────────────────────────────────────────────┘ │
│ ┌─ Assistant ──────────────────────────────────────┐ │
│ │ 好的，我看到这个函数有以下几个问题：                  │ │
│ │ 1. 错误处理不完善                                  │ │
│ │ 2. 性能可以优化...                                 │ │
│ │ ...                                                │ │
│ │ 我来帮你修改...                                    │ │
│ │ ◌ 正在思考...                                      │ │  ← spinner
│ └──────────────────────────────────────────────────┘ │
│ ┌─ 输入框 ─────────────────────────────────────────┐ │
│ │ > _                                                │ │
│ │ [Ctrl+Enter 提交]                                  │ │  ← 提示行
│ └──────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────┤  ← viewport 底部
│ $ _   ← 光标在下方（正常终端提示符）                     │
└─────────────────────────────────────────────────────┘
```

### 1.2 界面区域划分

| 区域 | 说明 | 高度 |
|------|------|------|
| 终端历史 | 用户启动 Codex 之前的 shell 输出 | 可变 |
| **聊天区域** | AI 对话渲染区 | 自适应 |
| ├ User cell | 用户消息（已提交） | 内容高度 |
| ├ Assistant cell | AI 回复（含代码、文件差异） | 内容高度 |
| ├ Status row | 正在思考/执行中的 spinner | 1 行 |
| └ **底部面板** | 输入框、审批、弹窗等 | 可变 |
| 终端提示符 | 退出后的正常 shell | — |

### 1.3 底部面板（Bottom Pane）

底部面板是交互的核心区域，采用**栈式视图管理**，可以 push/pop 不同视图：

```
┌─ 底部面板（默认：输入框） ──────────────────────────┐
│ > 帮我写一个 Rust 解析器_                             │
│ [Ctrl+Enter 提交]                                    │
└──────────────────────────────────────────────────────┘

┌─ 底部面板（审批弹窗） ──────────────────────────────┐
│ ┌─ 审批请求 ────────────────────────────────────┐  │
│ │ AI 想修改 src/parser.rs                        │  │
│ │ 差异: +36 / -12 行                            │  │
│ │ [Y] 接受  [N] 拒绝  [D] 查看差异               │  │
│ └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘

┌─ 底部面板（选择列表） ──────────────────────────────┐
│ ┌─ 选择模型 ────────────────────────────────────┐  │
│ │ → GPT-4o (推荐)                               │  │
│ │   GPT-4o-mini                                 │  │
│ │   o1-mini                                     │  │
│ │   o1-preview                                  │  │
│ └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

## 2. 用户工作流

### 2.1 主流程

```
启动 Codex
  │
  ├── 首次运行 → 配置向导（模型选择、权限设置）
  │
  ├── 恢复会话 → 选择之前的会话继续
  │
  └── 新会话
        │
        ▼
  输入提示词
        │
        ▼
  提交（Enter / Tab）
        │
        ▼
  AI 处理中...
   ├── ◌ Spinner 动画
   ├── ℹ 状态更新
   └── 子代理活动
        │
        ▼
  AI 输出结果
   ├── 文本回复
   ├── 代码块（可应用）
   ├── 文件修改（需审批）
   └── 命令执行（需审批）
        │
        ▼
  用户交互
   ├── 继续对话
   ├── 接受/拒绝修改
   ├── 允许/阻止命令
   └── 中断（Ctrl+C）
```

### 2.2 审批流程

```
AI 发起文件修改请求
  → 底部面板弹出审批视图
  → 用户选择：
      ├── Y / Enter → 接受修改
      ├── N → 拒绝修改
      ├── D → 查看差异预览
      └── A → 始终允许本次会话
  → 结果反馈给 AI
  → 继续对话
```

### 2.3 命令执行流程

```
AI 提议执行命令
  → 底部面板弹出命令审批视图
  → 用户选择：
      ├── Y → 允许执行
      ├── N → 阻止
      └── A → 始终允许本次会话
  → 命令执行
  → 输出结果返回给 AI
  → 继续对话
```

### 2.4 多代理工作流

```
用户提交复杂任务
  → 主代理接收任务
  → 主代理分解任务
  → 派发子任务到子代理
  → 子代理后台执行
  → 状态更新反馈到主区域
  → 子代理完成
  → 主代理汇总结果
  → 输出给用户
```

## 3. 按键映射

### 3.1 全局按键

| 按键 | 功能 | 说明 |
|------|------|------|
| `Enter` | 提交输入 | 普通模式下提交当前输入 |
| `Shift+Enter` | 换行 | 在输入框中换行 |
| `Tab` | 提交或排队 | 无任务时提交，有任务时排队 |
| `Ctrl+C` | 中断/取消 | 中断当前 AI 操作或取消弹窗 |
| `Ctrl+D` | 退出 Codex | 结束会话 |
| `Ctrl+Z` | 暂停（Unix） | 暂停 Codex，返回 shell |
| `Ctrl+T` | 转录覆盖层 | 查看完整对话历史 |
| `Ctrl+R` | 历史搜索 | 反向搜索输入历史 |

### 3.2 输入框按键

| 按键 | 功能 | 说明 |
|------|------|------|
| `↑/↓` | 历史导航 | 遍历输入历史 |
| `Ctrl+K` | 删除到行尾 | 删除光标到行尾的内容 |
| `Ctrl+U` | 删除到行首 | 删除光标到行首的内容 |
| `Ctrl+W` | 删除前一个词 | 删除光标前的一个词 |
| `Ctrl+A` | 到行首 | 移动光标到行首 |
| `Ctrl+E` | 到行尾 | 移动光标到行尾 |
| `Ctrl+←/→` | 按词移动 | 按词移动光标 |
| `/` | Slash 命令 | 触发 slash 命令弹出 |

### 3.3 审批视图按键

| 按键 | 功能 |
|------|------|
| `Y` / `Enter` | 接受 |
| `N` | 拒绝 |
| `D` | 查看差异 |
| `A` | 始终允许 |
| `Esc` | 取消 |
| `↑/↓` | 选择文件（多文件时） |

### 3.4 选择列表按键

| 按键 | 功能 |
|------|------|
| `↑/↓` | 选择项 |
| `Enter` | 确认选择 |
| `Esc` | 取消 |
| `/` | 搜索过滤 |

### 3.5 转录覆盖层按键

| 按键 | 功能 |
|------|------|
| `↑/↓` | 滚动 |
| `PgUp/PgDn` | 翻页 |
| `Enter` | 选择并插入到输入 |
| `Esc` | 关闭覆盖层 |

## 4. 视觉反馈系统

### 4.1 Spinner 动画

Codex 提供 10 种 spinner 动画风格，每帧 80ms 切换：

| 风格 | 视觉效果 |
|------|----------|
| `default` | │ ─ ─ │ / ─ ─ │ / ─ ─ │ ... |
| `codex` | ⌐ ◙ ◙ ◐ ◑ ◒ ◓ ● |
| `openai` | ◐ ◓ ◑ ◒ |
| `blocks` | █ ▓ ▒ ░ ▒ ▓ |
| `dots` | ⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ ⠇ ⠏ |
| `hash` | ▉ ▊ ▋ ▌ ▍ ▎ ▏ ▎ ▍ ▌ ▋ ▊ ▉ |
| `hbars` | ▏ ▎ ▍ ▌ ▋ ▊ ▉ ▊ ▋ ▌ ▍ ▎ |
| `vbars` | |

### 4.2 状态指示

| 状态 | 视觉表现 |
|------|----------|
| AI 正在思考 | Spinner 动画 + "正在思考..." |
| AI 正在执行 | Spinner 动画 + "正在编译..." |
| 等待审批 | 底部面板弹出审批视图 |
| 子代理活动 | 状态栏显示子代理数量 |
| 网络请求 | 速率限制指示器 |
| 错误 | 红色高亮错误信息 |

### 4.3 消息样式

| 消息类型 | 样式 |
|----------|------|
| 用户消息 | 普通文本 |
| AI 回复 | 普通文本 + 代码块高亮 |
| 代码块 | 语法高亮（bash 高亮） |
| 文件差异 | 绿色（+）/ 红色（-） |
| 系统消息 | 灰色/斜体 |
| 错误消息 | 红色 |
| 审批请求 | 带边框的弹窗 |

### 4.4 桌面通知

当终端窗口失焦时，Codex 可以发送桌面通知：

```
通知条件：
  - Unfocused（默认）：仅终端失焦时通知
  - Always：始终通知

通知时机：
  - AI 完成回复
  - 需要用户审批
  - 出现错误
```

## 5. 进程管理交互

### 5.1 暂停/恢复（Unix）

```
用户按 ^Z
  → 终端恢复到正常模式
  → 显示 "Suspended"
  → 用户执行其他命令
  → 输入 fg
  → Codex 恢复，所有状态保留
  → 继续对话
```

### 5.2 运行外部程序

当用户需要运行 `git`、`vim` 等程序时，Codex 会自动处理终端状态切换：

```
1. 用户输入需要运行外部程序
2. Codex 暂停事件轮询
3. 恢复终端模式
4. 运行外部程序
5. 程序退出后重新设置终端模式
6. 恢复事件轮询
7. 继续对话
```

## 7. 特殊交互场景

### 7.1 终端 Resize

```
用户调整终端窗口大小
  → 自动检测尺寸变化
  → 调整 viewport 位置：
      - 缩小 → 上滚历史区域
      - 变大 → 如果底部对齐，向下扩展
  → 重新渲染聊天区域
  → 保持光标位置正确
```

### 7.2 粘贴处理

```
用户粘贴文本（Ctrl+Shift+V 或鼠标中键）
  → 终端发送 bracketed paste 标记
  → 解析粘贴内容
  → 插入到输入框
  → 保持格式（多行文本）
```

### 7.3 外部编辑器

```
用户在输入框中触发外部编辑器（配置的编辑器）
  → 保存当前输入
  → 打开外部编辑器（如 vim）
  → 用户编辑
  → 保存并退出
  → 读取编辑内容
  → 恢复到输入框
```

## 8. 总结

Codex TUI 的交互设计遵循以下原则：

1. **最小侵入**：内联视图不占用全屏，保留终端原生体验
2. **可控安全**：每一步修改和执行都需要用户确认
3. **反馈及时**：Spinner、状态指示、通知确保用户知道 AI 正在做什么
4. **键盘驱动**：所有操作都可以通过键盘完成，无需鼠标
5. **状态可恢复**：`^Z` 暂停/恢复、会话恢复、回放等功能确保用户不会丢失上下文
