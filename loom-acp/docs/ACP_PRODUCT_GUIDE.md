# Loom ACP 升级产品说明书

> 从 v0.10 升级到 v0.11 — 面向产品、设计和项目管理团队
>
> 2025-08-19

---

## 一、背景

Loom 通过 ACP（Agent Client Protocol）协议与 IDE（Zed、JetBrains、Neovim 等）集成。用户在编辑器中打开 Loom 面板、输入指令、查看 Agent 执行结果，全流程由 ACP 定义通信规范。

当前 Loom 使用 ACP SDK **v0.10**。ACP 协议已发布 **v0.11.1**（Schema v0.11.7），包含一批已稳定的功能和多个实验性新能力。本文档从产品角度说明升级后用户可获得什么新体验。

---

## 二、升级概览

### 对用户意味着什么

| 维度 | 升级前（v0.10） | 升级后（v0.11） |
|------|----------------|----------------|
| 会话历史 | 只能创建新会话，无法浏览已有会话 | IDE 可列出所有历史会话，一键恢复 |
| 会话标题 | 标题固定或无标题 | Agent 可实时更新会话标题，帮助用户识别 |
| 模型切换 | 通过配置选项切换 | 相同，但实现更稳定 |
| 工具执行确认 | request_permission（允许/拒绝） | 未来可支持更丰富的交互式确认 |
| 扩展能力 | 仅支持 ACP 标准方法 | 支持自定义扩展方法，为 Loom 专属功能预留通道 |
| 会话关闭 | 只能关闭 IDE Tab，Agent 端无感知 | IDE 关闭 Tab 时 Agent 可立即释放资源 |
| 消息追踪 | 无法追踪消息 ID | 每条消息有唯一 ID，便于调试和排查 |
| 使用量统计 | 无 | 可向 IDE 报告 Token 消耗 |

## 三、已稳定功能 — 用户立即可用

### 3.1 会话列表（session/list）

**用户故事**

> 作为开发者，我在 IDE 中打开 Loom 面板时，想看到之前所有对话的列表——包括标题、时间和工作目录——这样我可以快速恢复上下文继续工作，而不必从头开始。

**功能描述**

- IDE 面板中展示 Loom 所有历史会话列表
- 每条记录显示：会话标题、工作目录、最后更新时间
- 用户点击任意一条即可恢复该会话
- 支持按工作目录过滤

**用户价值**

- 不丢失上下文：跨 IDE 重启、跨项目切换时保留完整对话
- 快速定位：通过标题和时间找到特定对话
- 减少重复劳动：避免对同一问题反复提问

**升级前状态**

- Loom 已实现 `list_sessions()`，但 IDE 端可能受限于 feature flag
- 升级后该功能正式稳定，所有 IDE 均可使用

---

### 3.2 会话元数据实时更新（session_info_update）

**用户故事**

> 作为开发者，我向 Loom 提了一个问题后，会话标题能自动变成一个简短的摘要（如"修复登录页的 CSS 布局问题"），这样我在会话列表里一眼就能找到它。

**功能描述**

- Agent 在对话过程中主动更新会话标题
- 不需要 IDE 轮询，实时推送
- 未来可扩展到状态更新（如"正在执行"、"等待确认"、"已完成"）

**用户价值**

- 会话列表始终有意义，不再是"新对话 1"、"新对话 2"
- 减少用户手动命名的负担
- 与 `session/list` 配合，形成完整的会话管理体验

**技术备注**

- 需要在 `stream_bridge` 中实现 Loom 事件到标题更新的转换逻辑
- 标题来源可以是 LLM 生成的摘要

---

### 3.3 会话配置选项（session/config options）

**用户故事**

> 作为开发者，我想在 IDE 面板的设置区域看到可切换的选项列表——比如选择模型（Claude Sonnet 4、GPT-4o）、切换模式（Code、Ask、Architect）——这样不用离开编辑器就能调整 Loom 行为。

**功能描述**

- Agent 在创建会话时声明可配置项
- IDE 渲染为下拉选择器或开关
- 用户修改后即时生效，无需重启
- 支持两种控件类型：
  - **下拉选择器**：模型选择、模式切换
  - **布尔开关**：启用/禁用某项功能

**用户价值**

- 所见即所得的配置体验
- 无需编辑配置文件
- 在对话过程中随时切换模型或模式

**升级前状态**

- Loom 已实现 `set_session_config_option()` 和 `set_session_mode()`
- 升级后 builder API 更标准，减少序列化 hack 带来的潜在 bug

---

### 3.4 扩展方法（ExtMethod）

**用户故事**

> 作为 Loom 产品团队，我们想在 IDE 面板中提供 Loom 独有的功能（如一键生成 PR 描述、批量重构建议），这些功能不在 ACP 标准里，但用户很需要。

**功能描述**

- ACP 允许 Agent 和 Client 之间发送自定义请求和通知
- 方法名以 `_` 前缀标识（如 `_loom/generate_pr_description`）
- 完全不影响标准 ACP 协议兼容性
- IDE 可以选择性地支持这些扩展方法

**用户价值**

- Loom 可以在 IDE 中提供差异化的高级功能
- 打破标准协议的限制，实现 Loom 独有的创新交互
- 与标准 ACP 功能和平共处

**升级前状态**

- v0.10 不支持扩展方法
- v0.11 新增必需方法 `ext_method()` 和 `ext_notification()`
- 初期实现为空壳（记录日志 + 默认响应），后续可逐步添加 Loom 专属功能

---

### 3.5 实现信息交换（clientInfo / agentInfo）

**用户故事**

> 作为开发者，我想在 Loom 面板中看到当前使用的 Loom 版本号和连接状态，遇到问题时方便排查。

**功能描述**

- 握手阶段 Agent 和 Client 交换名称、版本、标题
- IDE 可以在 UI 中展示 "Loom v0.1.6 — 已连接"
- 便于兼容性诊断和版本管理

**用户价值**

- 明确知道自己用的是哪个版本
- 版本不兼容时提前提示，避免奇怪的运行时错误
- 支持按 IDE 类型差异化行为（如 Zed vs JetBrains 的 UI 适配）

## 四、实验性功能 — 可选启用，前瞻布局

以下功能需要通过 feature flag 启用，尚未正式稳定。产品团队可以评估是否在当前版本中启用。

### 4.1 会话显式关闭（unstable_session_close）

**用户故事**

> 作为开发者，我在 IDE 中关闭了一个 Loom 对话 Tab，我希望 Loom 立即停止相关的后台任务并释放资源，而不是等进程退出才清理。

**功能描述**

- IDE 关闭会话 Tab 时向 Agent 发送 `session/close` 请求
- Agent 立即：停止正在执行的 LLM 调用、终止工具执行、释放内存
- 用户重新打开时不会遇到残留状态

**用户价值**

- 资源即时回收：CPU、内存、API 配额
- 状态干净：不会出现"幽灵任务"继续运行
- 与 IDE 的 Tab 生命周期一致

**建议：启用** — 实现成本低（调用 `SessionStore::remove()` + 取消 flag），用户感知明显

---

### 4.2 交互式确认（unstable_elicitation）

**用户故事**

> 作为开发者，当 Loom 要执行一个有风险的操作（比如删除文件、运行 shell 命令）时，我想要一个更丰富的确认界面——不只是"允许/拒绝"，还能看到具体影响、选择部分批准。

**功能描述**

- 在三种场景中支持交互式确认：
  1. **会话级别**：开始时的配置确认
  2. **工具调用级别**：执行前的详细确认（比现有 request_permission 更灵活）
  3. **请求级别**：运行中的信息收集
- 支持多种响应：确认/拒绝/取消 + 结构化数据

**用户价值**

- 更安全：工具执行前给用户更充分的信息
- 更灵活：不只有"全有或全无"
- 更智能：Agent 可以在确认过程中获取额外上下文

**建议：暂不启用** — 等 feature 稳定后再评估

---

### 4.3 消息 ID 追踪（unstable_message_id）

**用户故事**

> 作为开发者，我遇到 Loom 输出异常，想通过日志中的消息 ID 快速定位是哪一步出了问题。

**功能描述**

- 每条消息（请求、响应、通知）携带唯一 ID
- 日志中可按 ID 追踪完整的请求-响应链
- 便于去重和顺序保证

**用户价值**

- 排查效率提升：从"猜测哪个环节出错"到"按 ID 精确追踪"
- 与 IDE 厂商协作时提供精确的问题复现信息

**建议：可选启用** — 对调试有帮助，实现成本适中

---

### 4.4 会话使用量追踪（unstable_session_usage）

**用户故事**

> 作为开发者，我想在 IDE 面板底部看到当前对话消耗了多少 Token，这样我能控制成本。

**功能描述**

- Agent 向 IDE 报告会话的资源使用量
- 可展示：Token 消耗、API 调用次数
- IDE 可在 UI 中渲染为进度条或数字

**用户价值**

- 成本透明：用户始终知道消耗了多少 Token
- 行为调整：看到 Token 快用完时可以精简 prompt 或切换模型

**建议：可选启用** — 对付费 API 用户价值很高

---

### 4.5 会话恢复增强（unstable_session_resume）

**用户故事**

> 作为开发者，我想恢复之前的对话，并且 Loom 能记住上次中断时正在执行的任务，接着做而不是重新做。

**功能描述**

- 比 `load_session` 更细粒度的恢复能力
- 可能支持：恢复到特定状态点、恢复工具调用上下文
- 与 Loom 的 checkpointer 功能协同

**用户价值**

- 无缝恢复：感觉就像从未离开
- 保留中间状态：长任务的进度不会丢失

**建议：评估后决定** — 需要确认与现有 `load_session` 的差异

---

### 4.6 其他实验性功能

| 功能 | 一句话描述 | 建议 |
|------|-----------|------|
| 多认证方式 | 支持 OAuth、API Key 等多种认证 | 暂不需要 |
| LLM 提供商 | 向 IDE 声明支持的 LLM 列表 | 当前 config options 已满足 |
| 取消请求 | 精确取消特定请求 | 暂不需要 |
| 额外目录 | 多项目工作区支持 | 等需求明确 |
| 登出 | 清除认证状态 | 暂不需要 |
| NES | 网络扩展机制 | 协议设计中，暂不需要 |

## 五、版本完整性说明

### 5.1 版本链路

当前项目从 v0.10 升级，需要经过以下完整链路：

```
v0.10.x (当前)  ──→  v0.11.0 (SDK 重构)  ──→  v0.11.1 (bug fix)
                        │
                        └── Schema 同步升级链路:
                            v0.11.0 → v0.11.1 → v0.11.2 → ... → v0.11.7
```

| 组件 | 当前版本 | 升级目标 | crates.io 最新 |
|------|---------|---------|---------------|
| `agent-client-protocol` (SDK) | 0.10 | **0.11.1** | 0.11.1 |
| `agent-client-protocol-schema` (Schema) | 0.10.x | **0.11.7** | 0.11.7 |

> 注意：Protocol spec 已有 **v0.12.x**，但 Rust SDK 尚未跟进。本次升级范围是 SDK 0.11.1 + Schema 0.11.7，不含 0.12.x。

### 5.2 SDK 各版本变更

| 版本 | 日期 | 关键变更 |
|------|------|---------|
| 0.11.1 | 2026-04-21 | 移除 `boxfnonce` 依赖 |
| 0.11.0 | 2026-04-20 | **SDK 架构重构**、迁移指南、RPC 层 3 项修复 |
| 0.10.4 | 2026-03-31 | 0.10 最后一个版本 |

### 5.3 Schema 各版本变更

| 版本 | 日期 | 关键变更 |
|------|------|---------|
| 0.11.7 | 2026-04-15 | Providers 初始实现 |
| 0.11.6 | 2026-04-14 | `available_commands_update` 增强 |
| 0.11.5 | 2026-04-09 | Session/tool call/request 级 elicitation |
| 0.11.4 | 2026-03-28 | NES 初始实现 |
| 0.11.3 | 2026-03-18 | Elicitation schema 增强、logout 实现 |
| 0.11.2 | 2026-03-11 | `session/stop` → `session/close` 完整重命名 |
| 0.11.1 | 2026-03-09 | 稳定 `session/list` + `session_info_update` |
| 0.11.0 | 2026-03-04 | Session/stop、message ID、auth methods、boolean config |

## 六、升级影响总结

### 6.1 对用户的影响

| 影响类型 | 描述 |
|---------|------|
| **正向体验** | 会话管理更完善（列表、标题更新、显式关闭） |
| **正向体验** | IDE 中可直接配置模型和模式 |
| **正向体验** | 扩展方法为 Loom 差异化功能铺路 |
| **潜在风险** | 升级过程中可能有短暂不可用（需要重新编译部署） |
| **兼容性** | v0.11 与 v0.10 不兼容，需同时升级 SDK 和 IDE 插件版本 |

### 6.2 对开发团队的影响

| 影响类型 | 描述 |
|---------|------|
| **必须做** | 实现 `ext_method()` 和 `ext_notification()`（否则编译失败） |
| **建议做** | 替换 serde_json hack 为原生 builder API |
| **建议做** | 启用 `unstable_session_close` |
| **可选做** | 启用 `unstable_message_id`、`unstable_session_usage` |
| **不做** | 其他 unstable features 暂不启用 |

### 6.3 对 IDE 合作方的影响

| 影响类型 | 描述 |
|---------|------|
| **必须同步** | IDE 端需要使用对应的 v0.11 Client SDK |
| **新能力** | 可渲染 `session/list`、`session_info_update` |
| **新能力** | 可发送 `session/close` 请求 |
| **新能力** | 可调用 Agent 的 `ext_method` |

## 七、时间线和优先级建议

```
Phase 0 (0.5天)     ─── 准备工作
Phase 1 (1-2天)     ─── 编译通过 ← 优先级最高
Phase 2 (1-2天)     ─── API 适配 ← ext_method 为 P0
Phase 3 (1天)       ─── 测试修复
Phase 4 (0.5-1天)   ─── session_close 等可选功能
Phase 5 (0.5天)     ─── 验证收尾
总计: 4.5-7 个工作日
```

**产品建议的优先级排序**：

1. **必须交付** — 会话列表稳定化、ext_method 支持、Builder API 清理
2. **建议交付** — 会话显式关闭、会话标题更新
3. **后续迭代** — 使用量追踪、消息 ID、交互式确认
